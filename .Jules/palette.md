## 2024-05-24 - Interactive Controls Custom Styling Impact on Keyboard Accessibility Focus States
**Learning:** When applying custom styling to native input controls like sliders (`input[type="range"]`) or buttons (e.g. stripping native borders/backgrounds to use custom design tokens like `--surface-highest`), the browser's default `outline` for `:focus-visible` is often implicitly overridden or becomes visually hidden due to contrast issues or explicit `outline: none` declarations. Additionally, Playwright's default `page.focus()` may not trigger `:focus-visible` because it acts as a script-based focus rather than simulating real user keyboard navigation.
**Action:** When restyling native interactive controls with custom themes, always explicitly redefine `:focus-visible` styles using the design system's primary color (`var(--primary)`) with an `outline-offset` to ensure clear keyboard navigation visibility. For automated visual testing of these states, use `page.keyboard.press('Tab')` after focusing to correctly simulate user keyboard interaction and trigger the pseudo-class.
