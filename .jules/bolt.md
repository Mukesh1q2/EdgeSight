## 2024-06-12 - datetime.strptime Botteneck in High-Frequency Loops
**Learning:** Using `datetime.strptime` inside hot loops (like FastAPI's `detection_loop` which iterates constantly) to parse time-only strings (e.g. `"%H:%M:%S"`) for simple time-difference calculations introduces a significant performance bottleneck. This codebase uses string timestamp diffs for rate limiting fall alerts, which drastically consumes CPU cycles unnecessarily compared to basic float math. Additionally, `datetime.strptime` with time-only strings defaults the date to 1900-01-01, meaning timedelta comparisons against `datetime.now()` risk being severely buggy over time.
**Action:** Always use float timestamps (`time.time()`) and simple subtraction for internal rate-limiting and performance tracking in async background loops. Reserve string parsing and `strftime` strictly for final serialization and user-facing displays.
