## 2024-06-18 - [FastAPI Backend] String Parsing in High-Frequency Loops
**Learning:** The background `detection_loop` in `fastapi_server.py` runs at ~30 FPS. It included a 2-second rate-limiter for fall alerts that was implemented by pulling the timestamp of the last alert (stored as a string "%H:%M:%S") and parsing it with `datetime.strptime` inside the loop. Benchmarking showed that string parsing with `strptime` takes ~2.0 seconds per 100,000 iterations, whereas simple float subtraction with `time.time()` takes ~0.02 seconds (a 100x improvement). Additionally, the dictionary holding the new alert payload was constructed before the rate-limit condition was evaluated, meaning unused dictionaries were continuously allocated and discarded during the 2-second cooldown, adding unnecessary garbage collection overhead.
**Action:** Always scrutinize high-frequency asynchronous loops (like video stream handlers) for hidden expensive operations like string-based date parsing or premature object allocation. Default to float timestamps (`time.time()`) for internal state tracking and rate-limiting, and defer object creation until after conditions have passed.
