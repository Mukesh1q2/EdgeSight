## 2024-05-26 - High-Frequency Loop Bottlenecks (datetime vs time)
**Learning:** In high-frequency operations like the main `detection_loop` (~30 FPS), parsing and formatting strings for date math (e.g., using `datetime.strptime` to parse an already formatted string just to calculate elapsed time) introduces significant CPU overhead and can cause micro-stutters or missed frames. Running a local benchmark showed `datetime.strptime` takes ~1.46s per 100k iterations compared to ~0.017s for a float comparison using `time.time()`.
**Action:** Always prefer primitive float timestamps (`time.time()`) for rate limiting and state tracking instead of expensive string-based operations like `datetime.strptime` and `strftime`. Only execute string formatting (e.g., `datetime.now().strftime`) when strictly necessary (e.g., right before yielding or saving the payload), deferring it until after prerequisite conditions (like cooldown periods) have passed.
